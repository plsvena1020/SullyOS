# 宽而矮窗口 · 主页布局修正设计（2026-09-12）

> 背景：用户在电脑上把浏览器窗口拉成全宽、矮条（高度低于 600px）时，布局自动掉进手机形态；
> 手机主页是竖屏比例的固定满高布局，内容被上下裁掉。用户要求：电脑端判定区间更大；
> 手机形态装不下时先自动紧凑，仍装不下可纵向滚动。

## 一、现状与根因

1. 布局判定 `utils/layoutMode.ts:19-20`：`width >= 1024 && height >= 600` 才进电脑形态。
   全宽（>= 1024）但矮（< 600）的窗口因此进入手机形态。
2. 手机形态主页每页固定满高、不可纵向滚动：
   - 翻页容器 `overflow-y-hidden`（`apps/Launcher.tsx:910`）；
   - 页容器 `h-full` 且 `contain: layout paint`（`apps/Launcher.tsx:926-927`），内容溢出即被裁。
3. 第 2 页（日程 + 四宫格）内层用 `justify-center`（`apps/Launcher.tsx:947`），
   内容溢出时上下两头同时被裁；四宫格单元 `aspect-square` 随宽度膨胀，窗口越宽越容易溢出。
4. 仓库记录自认现状：`plans/2026-09-11-wheel-pager-scroller-detect.md:80`
   「窗口高度小于手机设计高度时主页内容被裁的部分仍看不到（现状如此），本单只恢复翻页」。

## 二、目标行为

1. **电脑端判定 = 半屏规则 + 绝对下限**：电脑屏幕上 `width * 2 >= screen.width`
   （贴靠半屏也算）或 `width >= 900` 即电脑形态；手机/平板屏幕（`screen.width < 1000`）
   不参与半屏比例（移动端全屏窗口永远是「长于半屏」，否则手机会被误判），沿用 `width >= 1024`。
   高度不参与。900 下限的取法：电脑版两栏主页在 900 宽时稳定成立（左栏 clamp 下限 280 + 网格约 490）。
   宽而矮的窗口留在电脑版；电脑主页本来就是「左栏 / 网格 / Dock 各自内部滚动」的自适应结构。
2. **手机形态装不下时**：
   - 先自动紧凑：页面可视区（横向翻页容器）高度 < 540px 时，缩小时钟 / 角色卡 / 图标并收紧留白；
   - 仍装不下：整页等比缩小到一屏内（`FitPage`，scale = 可视高度 / 内容自然高度），**不做纵向滚动**。
3. **正常手机尺寸零变化**：页面可视区 >= 540px 时外观与现状完全一致，不出现多余滚动。

## 三、设计决定

### D1 电脑判定 = 半屏比例 + 绝对下限 + 移动端护栏

- `isDesktopLayoutViewport(width, screenWidth)`：
  - `screen.width >= 1000`（电脑级屏幕）：`width >= 900 || width * 2 >= screen.width`；
  - 否则（手机/平板）：`width >= 1024`（沿用旧口径）。
- 理由：手机形态是竖屏比例设计，宽而矮窗口与它根本错配；电脑形态的组件各自可滚，任意高度都可降级使用。
  半屏规则让电脑窗口按屏幕比例切换；移动端护栏避免手机全屏窗口永远「长于半屏」而被误判成电脑版。
- 影响面：`DesktopDock`（5 个图标约需 381px）加 `overflow-y-auto` 兜底极矮窗。

### D2 手机形态紧凑档 = 按页面可视区高度触发

- 在 `apps/Launcher.tsx` 用 `ResizeObserver` 量横向翻页容器的 `clientHeight`；
  `< 540` 进入紧凑档。540 的取法：非紧凑首屏内容约需 528px，取 540；
  iPhone SE 页面可视区约 559px、常规手机更高，不会误触发。
- 紧凑内容只复用既有能力：`DesktopClock compact` / `CharacterWidget compact` /
  `AppGridPage` 新增 `compact`；页面留白 `px-6 pt-12 pb-8` → `px-4 pt-7 pb-6`；
  第 2 页四宫格总宽 `max-w-[24.75rem]`（紧凑档 `19rem`）；第 3 页顶部方图各 `max-w-[11rem]`、
  横图 `h-32 → h-24`。

### D3 装不下的兜底 = 整页等比缩小（不做滚动）

- 新增 `FitPage`（`apps/Launcher.tsx`）：外层保持页容器与原 class/style，内层包一层
  `w-full h-full flex flex-col`；`scale = min(1, 内层可视高 / 内层内容自然高)`，
  `transform-origin: top center`。装得下时 scale = 1（手机正常尺寸零变化）；
  装不下时整页缩小到一屏内，不产生滚动。
- 离屏页被 `content-visibility` 跳过，激活当前页时补量（rAF + 180ms 各一次）；
  可视区尺寸变化由 ResizeObserver、内容变化（数据加载/文案/图片挂载）由 MutationObserver 触发重量。
- 方形组件按手机尺度限宽，避免宽窗下被拉成巨图把页面撑爆：第 2 页四宫格容器限宽，
  第 3 页顶部两张方图各限宽；容器的限宽都大于手机实际可用宽，手机端不生效。
- 第 2 页 `justify-center` 换安全居中（`flex-1` 外层 + 内层 `my-auto`）。
- 末页 `WidgetsPage` 去掉内部 `overflow-y-auto`，交给 `FitPage` 统一缩放。

## 四、边界

- 不动横向翻页 / 滚轮语义、不动 `DesktopAppGrid` / `fitGrid`、不动各皮肤主页
  （mobilegame / 电子宠物 / 伴侣为自渲染布局，另有滚动）。
- 手机端正常尺寸外观零变化；只有页面可视区 < 540px 才进入紧凑档。
- 不改 `desktopMode` 手动三档语义（`on` / `off` 仍覆盖尺寸判定）。
- 小修复，不 bump `APP_VERSION`。

## 五、验收标准

- 1600×500 / 1024×500：电脑形态，主页无手机版裁切；左栏与网格可滚；Dock 图标可达。
- 1017×890（用户实测窗口）：电脑形态（≥ 900），电脑版导航与一屏网格直接可用。
- 900×700：手机形态，外观与改动前一致，首屏完整。
- 900×500 及更矮：手机形态紧凑档；再矮时整页等比缩小，所有组件仍在同一屏内可见（无纵向滚动）。
- 393×852（真机 / 设备模拟）：外观零变化，无缩放，横向翻页正常。
- 长按编辑态拖拽与 Dock 互换不受影响。
